# 数据库选型与 SQL 方言适配器

## 1. 默认选择

默认优先关系型数据库。除非用户明确是本地工具、桌面轻量应用、纯缓存/队列、嵌入式场景，否则不要一开始把 SQLite 或 Redis 当线上主库。

## 2. PostgreSQL

适合：

- 强事务与复杂约束。
- 复杂业务关系。
- 报表与复杂查询。
- 多租户系统。
- 需要 JSONB、partial index、range type、CTE、窗口函数等能力。

设计建议：

- 主键可使用 `BIGINT GENERATED BY DEFAULT AS IDENTITY` 或 UUID。
- 金额使用 `BIGINT amount_cents` 或 `NUMERIC(12,2)`。
- 状态可用 `TEXT + CHECK` 或 enum；业务频繁变动时，优先 `TEXT + CHECK` 或字典表，避免 enum 迁移复杂。
- 高频软删除查询可使用 partial index：`CREATE INDEX ... WHERE deleted_at IS NULL`。
- 唯一业务键要用 `UNIQUE` 约束，不只靠应用判断。
- 复杂时间段预约可考虑 range type，但首版可先用 `starts_at` / `ends_at`。

## 3. MySQL

适合：

- 常规 Web、电商、后台管理。
- 团队已有 MySQL 经验。
- 对生态兼容性要求高。

设计建议：

- 引擎默认 InnoDB。
- 外键定义在 child table 上。
- 金额使用 `BIGINT amount_cents` 或 `DECIMAL(12,2)`。
- 状态可用 `VARCHAR` + 应用枚举，也可结合 CHECK，但要注意版本与约束支持。
- 字符集推荐 `utf8mb4`。
- 大表 DDL 要评估锁和执行时间。

## 4. SQLite

适合：

- 本地工具。
- 桌面应用。
- 移动端本地存储。
- 单机小型应用。
- 原型验证。

谨慎使用：

- 多服务共享同一数据库。
- 高写并发。
- 应用和数据分离在网络两端。
- 复杂线上业务主库。

## 5. Redis

Redis 可以作为缓存、短期状态、队列、实时流、向量检索或特定场景的 primary/custom database，但在常规业务系统中不要默认替代关系型主库。

适合：

- 登录态/session。
- 验证码。
- 限流计数。
- 热点数据缓存。
- 排行榜。
- 短期锁。
- Pub/Sub 或 Streams。
- 向量检索 / 实时上下文。

不适合默认承担：

- 订单主数据。
- 财务对账主记录。
- 长期审计日志唯一存储。
- 复杂关系和强一致约束。

## 6. SQL 输出规范

原生 SQL 交付必须包含：

- `CREATE TABLE`。
- 主键、外键、唯一约束、CHECK、NOT NULL、DEFAULT。
- 索引。
- 软删除字段。
- 注释或表说明。
- 插入测试数据。
- 验收查询。
- 回滚/前滚说明。

## 7. 示例：PostgreSQL 基础字段

```sql
CREATE TABLE users (
  id BIGINT GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
  email TEXT NOT NULL,
  password_hash TEXT NOT NULL,
  status TEXT NOT NULL DEFAULT 'active' CHECK (status IN ('active', 'disabled')),
  created_at TIMESTAMPTZ NOT NULL DEFAULT now(),
  updated_at TIMESTAMPTZ NOT NULL DEFAULT now(),
  deleted_at TIMESTAMPTZ,
  CONSTRAINT users_email_unique UNIQUE (email)
);

CREATE INDEX users_active_created_at_idx
  ON users (created_at DESC)
  WHERE deleted_at IS NULL;
```
