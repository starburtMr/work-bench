# Stage-Aware Emergency Safety Gate Checklist

> 在普通诊断前先跑这一页。先判断项目阶段和风险适用性，再决定 `STOP / CONTAIN / CONTINUE`。尚未开发到的能力不要误报为当前阻塞。

## 1. 项目阶段

- [ ] `prototype`：本地原型/demo，无真实用户、真实数据、真实密钥、共享数据库。
- [ ] `mvp-dev`：MVP 开发中，开始形成数据/API/权限边界。
- [ ] `staging`：准备演示、内测、交付验收或共享环境联调。
- [ ] `production`：已有真实用户、真实数据、真实支付/消息/第三方调用。
- [ ] `handoff`：外包交付、团队接手或准备移交。
- [ ] `unknown`：证据不足，无法判断阶段。

## 2. 风险适用性

每个高危项先标注：

- [ ] `适用`：已有对应能力、数据、环境或代码证据。
- [ ] `暂不适用`：当前阶段还没有该能力，也没有真实环境证据。
- [ ] `未来门禁`：当前不适用，但进入 staging/production 或实现该能力前必须补齐。
- [ ] `不可验证`：无法判断是否适用。

## 3. STOP 信号

- [ ] 可能有生产数据，但没有备份、回滚或只读保护。
- [ ] migration/seed/reset 脚本可能删除或覆盖真实数据。
- [ ] 明文密钥、token、数据库密码、私钥、支付密钥进入仓库。
- [ ] 鉴权/权限绕过影响真实用户或管理后台。
- [ ] 支付、账务、订单金额、库存扣减存在不可逆错误风险。
- [ ] 真实邮件、短信、支付、第三方生产接口可能被测试命令触发。
- [ ] 隐私/敏感信息被日志、前端、错误响应或导出接口泄露。
- [ ] 部署流程不可回滚，且当前改动影响生产。
- [ ] 数据库结构与代码严重不一致且已有共享环境。

## 4. CONTAIN 信号

- [ ] 没有完整产品范围，但正在继续写新功能。
- [ ] API 文档、前端 client、后端路由明显漂移。
- [ ] schema/model/migration 三者至少两个不一致。
- [ ] CI 不跑真实命令，或 README 命令不可用。
- [ ] 包管理器混用、锁文件冲突、依赖来源不明。
- [ ] 大量 AI 生成代码没有边界、测试或 owner。
- [ ] 没有日志/requestId/错误结构，难以排查事故。
- [ ] 缺少回归测试，但要进入演示/交付。
- [ ] 是否有生产/真实数据、真实密钥或共享环境不可验证。

## 5. 原型期降噪

- [ ] 没有真实用户、真实数据、真实密钥、真实第三方服务或共享数据库证据时，不因“尚无支付/权限/隐私设计”直接判 `STOP`。
- [ ] V1 scope 未包含支付/权限/隐私/生产部署时，相关问题标为 `未来门禁`。
- [ ] 发现 `.env`、支付字段、admin 路由、migration、生产 URL、真实第三方 SDK 配置时，重新评估适用性。

## 6. CONTINUE 条件

- [ ] 项目阶段已判断。
- [ ] 高危项适用性已判断。
- [ ] 未发现 STOP 信号。
- [ ] 如有 CONTAIN 信号，已明确限制继续开发范围。
- [ ] 诊断过程不会修改业务代码、数据或远端服务。
- [ ] 关键证据来源可读取。

## 7. 输出语句模板

- `STOP`：当前命中高危止血条件：`...`。建议暂停普通开发，先执行隔离/备份/撤权/真源补救。
- `CONTAIN`：当前可继续诊断，但不建议新增功能。继续边界是：`...`。
- `CONTINUE`：当前未发现高危止血信号，可进入完整阶段矩阵诊断。
- `未来门禁`：当前阶段暂不适用，但进入 `...` 前必须补齐：`...`。
