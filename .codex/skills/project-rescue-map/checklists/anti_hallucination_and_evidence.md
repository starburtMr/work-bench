# Anti-Hallucination and Evidence Checklist

## 1. 判断前检查

- [ ] 每个“通过”都有 E4/E5，或至少 E2/E3 且明确说明尚未运行验证。
- [ ] 每个“部分具备/缺失/冲突/过时/不可验证”都有路径、命令或扫描范围证据。
- [ ] 没有把文件名、目录名、框架名当成事实。
- [ ] 没有把 README 描述当成代码真实状态。
- [ ] 没有把测试文件存在当成测试通过。
- [ ] 没有把 OpenAPI/接口文档存在当成前后端一致。
- [ ] 没有把 schema/model 存在当成 migration 安全。
- [ ] 没有把 CI workflow 存在当成 CI 有效。
- [ ] 推导项已标注 `合理推导` 或 `待确认`。

## 2. 报告前检查

- [ ] 诊断范围写清楚。
- [ ] 未读取/不可读取证据写清楚。
- [ ] 未执行命令写清楚，不能伪造结果。
- [ ] 风险等级和建议动作一致。
- [ ] 补救路线只指向已有 work-bench skill。
- [ ] 如果建议继续开发，继续边界和复查条件明确。
- [ ] 如果存在阻塞项，不能给“可继续”的无条件结论。

## 3. 高风险措辞禁用

不要写：

- “应该没问题”。
- “看起来能跑”。
- “应该有测试”。
- “可以直接上线”。
- “只需要小改一下”。

改写为：

- “当前没有 E4/E5 证据证明可运行”。
- “发现 E2 文档证据，但缺 E3/E4 验证”。
- “此项为合理推导，需要回到 X skill 确认”。
