# Release / Continuation Decision Playbook

## 目标

判断项目应当继续开发、条件继续、冻结普通开发、重开关键阶段，还是暂停/终止投入候选。

## 决策输入

- 阶段缺口矩阵。
- 风险登记表。
- 止血门结论。
- 交付/上线约束。
- 业务 owner 的不可接受风险。

## 决策树

### 1. 是否有 STOP 风险？

- Yes：结论为 `冻结普通开发`，先处理止血项。
- No：进入下一步。

### 2. 产品目标是否可验收？

- No：回到 `idea-check`，结论最多 `条件可继续`。
- Yes：进入下一步。

### 3. 数据/API 是否一致？

- No：回到 `data-map -> talk-link`，冻结依赖这些契约的新功能。
- Yes：进入下一步。

### 4. 质量/安全/回滚是否满足交付？

- No：回到 `final-check` 前置补救，结论不能是发布通过。
- Yes：可给 `可继续` 或进入发布验收。

### 5. 成本是否超过重开阶段成本？

- 如果修补成本大于局部重做，建议 `建议重开关键阶段`。
- 如果业务目标已失效或风险不可接受，标记 `终止或暂停投入候选`，交给业务 owner 决策。

## 输出

| 决策 | 条件 | 下一步 |
|---|---|---|
| 可继续 | 无阻塞，关键阶段证据足够 | 进入 work-plan 或 final-check |
| 条件可继续 | 有必须补项但可隔离 | 按补救主线推进 |
| 冻结普通开发 | 有 STOP/高危阻塞 | 先止血 |
| 建议重开关键阶段 | 局部重做比修补更安全 | 回到对应阶段 skill |
| 终止或暂停投入候选 | 目标/风险/成本不可接受 | 业务 owner 决策 |
