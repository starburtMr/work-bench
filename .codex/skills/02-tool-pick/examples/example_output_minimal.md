# 示例输出摘要

> 这是一个简化示例。正式输出应使用完整模板，并实时核查官方资料、维护状态和 License。

## 产品形态判断

唯一推荐产品形态：Web 后台管理系统。

原因：当前核心使用场景是教练管理会员、预约、训练记录和数据统计，表格、表单、权限和数据管理密集，优先做 Web 后台比一开始做 APP 或小程序更低成本、更易维护。

## 唯一推荐技术栈

前端：Vue 3 + Vite + Element Plus
后端：NestJS + TypeScript
数据库：PostgreSQL
ORM：Prisma
鉴权：JWT + RBAC
部署：前端部署到静态托管平台，后端和数据库部署到云服务器或托管数据库

## 为什么这是唯一推荐方案

1. 项目是典型中后台系统，Element Plus 能快速覆盖表格、表单、弹窗、分页、筛选等核心界面。
2. 用户是新手，Vue 3 的工程心智负担较低，AI 也容易按组件结构输出稳定代码。
3. 后端选择 NestJS 是因为它提供模块化结构，更适合长期维护，避免 Express 项目后期自由散乱。
4. 数据是会员、课程、预约、付款记录，关系型结构明显，PostgreSQL 比 NoSQL 更适合。
5. Prisma 能降低数据库访问复杂度，类型提示清晰，适合 AI 生成一致的数据库访问代码。

## 禁用技术清单

1. 不引入微服务。
2. 不引入 Kubernetes。
3. 不引入 GraphQL。
4. 不混用 React 和 Vue。
5. 不自研 UI 组件库。
6. 不在 MVP 阶段引入消息队列。
7. 不私自更换数据库。

## 重评触发条件

1. 教练用户超过 500 人。
2. 日活超过 5,000。
3. 数据量超过 1,000 万条。
4. 需要多端小程序并且 Web 后台不能覆盖核心场景。
5. 当前部署方案无法满足稳定性或成本要求。
