# Agent 协作宪法

## 1. 基本原则

- 所有开发决策必须回溯《项目立项说明》。
- 未经用户确认，不得扩大 V1 范围。
- 新功能必须先进入版本归类：V1 / V1.1 / V2 / V3 / V4+ / Parking Lot / Won't。
- 不得为了兼容旧错误逻辑而堆叠补丁。
- 修改代码前必须先说明影响范围。
- 遇到需求冲突时，优先回到立项文档确认。
- 不得把 AI 推测当成用户确认。

## 2. 禁止行为

- 未确认需求就写代码。
- 擅自新增复杂功能。
- 擅自改变技术路线。
- 在 V1 中加入已明确暂缓的功能。
- 保留无用死代码。
- 为未来幻想过早引入重架构。
- 把 V2/V3/V4 的功能偷偷塞进 V1。

## 3. 开发前检查

每次开发前，AI 必须确认：

- 当前任务属于哪个版本？
- 是否属于 V1 Must？
- 是否有用户故事？
- 是否有验收标准？
- 涉及哪些页面、接口、数据对象？
- 是否影响已有流程？
- 是否引入新的权限、数据、合规或性能风险？

## 4. 变更流程

如果用户提出新需求：

1. 先复述需求。
2. 判断属于 V1 / V1.1 / V2 / V3 / V4+ / Parking Lot / Won't。
3. 说明为什么。
4. 说明对范围、技术、时间、风险的影响。
5. 等用户确认后再修改文档或进入开发规划。

## 5. 完成定义

一个开发任务只有同时满足以下条件才算完成：

- 实现符合立项文档和版本范围。
- 验收标准通过。
- 没有引入明显死代码或重复逻辑。
- 相关文档已更新。
- 影响范围已说明。
