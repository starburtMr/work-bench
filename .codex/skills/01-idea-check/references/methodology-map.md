# 方法论映射

本 Skill 融合了以下主流方法论，并把它们转化成 AI 立项讨论动作。

## 1. Double Diamond / Design Council

用途：组织立项过程的“发散 → 收敛 → 方案 → 交付”。

Skill 中的对应动作：

- Discover：探索用户、场景、痛点、替代方案。
- Define：收敛问题、目标用户、核心价值、V1 闭环。
- Develop：提出 MVP 切法、版本路线、技术路径、风险缓解。
- Deliver：沉淀立项文档、验收标准、路线图。

参考：

- https://www.designcouncil.org.uk/resources/framework-for-innovation/

## 2. IDEO Design Thinking / Human-Centered Design

用途：确保方案同时满足人的需要、商业可持续、技术可行。

Skill 中的对应动作：

- Desirability：用户是否真的要。
- Viability：商业、运营、资源、合规是否可持续。
- Feasibility：技术上能否低成本实现。
- Inspiration / Ideation / Implementation：从理解用户，到生成方案，再落地验证。

参考：

- https://designthinking.ideo.com/
- https://www.designkit.org/human-centered-design.html

## 3. Lean Startup

用途：让 V1 成为学习工具，而不是功能堆砌。

Skill 中的对应动作：

- V1 只验证一个核心假设。
- 用最小闭环产生被验证的学习。
- 每个版本都定义验证信号和下一步决策。

参考：

- https://theleanstartup.com/principles

## 4. Jobs To Be Done / Strategyn

用途：把“用户要功能”翻译成“用户要完成的任务/进步”。

Skill 中的对应动作：

- 使用 JTBD 句式。
- 追问情境、触发点、当前替代方案、用户想获得的结果。

参考：

- https://strategyn.com/jobs-to-be-done/

## 5. Value Proposition Canvas / Strategyzer

用途：明确 Jobs、Pains、Gains 与产品价值之间的关系。

Skill 中的对应动作：

- Jobs：用户想完成什么。
- Pains：当前痛苦和阻碍。
- Gains：期待收益。
- Pain Relievers / Gain Creators：产品如何减痛和增益。

参考：

- https://www.strategyzer.com/library/the-value-proposition-canvas

## 6. MoSCoW / Agile Business Consortium

用途：做 MVP 优先级和版本边界。

Skill 中的对应动作：

- Must：没有它，V1 不成立。
- Should：重要但可延后。
- Could：锦上添花。
- Won't：本阶段明确不做。

参考：

- https://www.agilebusiness.org/resource/what-is-moscow-prioritization/

## 7. DMAIC / ASQ Six Sigma

用途：把模糊需求变成可定义、可度量、可分析、可改进、可控制的项目。

Skill 中的对应动作：

- Define：定义用户、问题、目标、范围。
- Measure：定义指标和验收。
- Analyze：分析流程、数据、风险。
- Improve：收敛 MVP 和方案。
- Control：用文档和版本门禁防止项目漂移。

参考：

- https://asq.org/quality-resources/dmaic

## 8. Scrum Guide

用途：定义版本目标、增量和完成标准。

Skill 中的对应动作：

- Product Goal：产品长期目标。
- Sprint/Version Goal：当前版本为什么有价值。
- Increment：每个版本必须形成可用价值增量。
- Definition of Done：完成标准必须透明、可检查。

参考：

- https://scrumguides.org/scrum-guide.html

## 9. Shape Up / Basecamp

用途：防止“2.0 大泥球”、无边界重构和过早承诺。

Skill 中的对应动作：

- Raw idea 不能直接开干。
- Appetite：定义投入胃口。
- Fixed time, variable scope：固定投入，裁剪范围。
- Rabbit holes：提前识别复杂坑。
- No-gos：明确不做。
- 防止 grab-bag 式项目。

参考：

- https://basecamp.com/shapeup/1.1-chapter-02
- https://basecamp.com/shapeup/1.2-chapter-03

## 10. Journey Mapping / Nielsen Norman Group

用途：用用户目标串联页面、动作、情绪、系统响应和机会点。

Skill 中的对应动作：

- 用户目标 → 用户动作 → 系统响应 → 数据变化 → 结果反馈。
- 避免只有功能清单，没有用户路径。

参考：

- https://www.nngroup.com/articles/journey-mapping-101/

## 11. User Stories / Agile Alliance

用途：把需求改写成用户价值表达，并为开发前验收做准备。

Skill 中的对应动作：

- “作为【用户】，我想要【目标】，以便【价值】。”
- 使用 INVEST 检查用户故事质量。

参考：

- https://agilealliance.org/glossary/user-stories/
- https://agilealliance.org/glossary/invest/

## 12. Product Roadmap / Atlassian

用途：把愿景、方向、优先级和进展整合成共享真源。

Skill 中的对应动作：

- V0/V1/V1.1/V2/V3/V4+ 分阶段路线图。
- 使用条件触发，而不是空想时间表。
- 让 roadmap 成为沟通和决策工具。

参考：

- https://www.atlassian.com/agile/product-management/product-roadmaps

## 13. North Star / HEART Metrics

用途：定义 V1 之后如何判断产品价值是否被验证。

Skill 中的对应动作：

- 1 个北极星指标或核心价值指标。
- HEART / AARRR 可作为辅助指标。
- 早期不做复杂指标体系，只定义关键成功信号。

参考：

- https://amplitude.com/books/north-star/about-north-star-framework
- https://research.google/pubs/measuring-the-user-experience-on-a-large-scale-user-centered-metrics-for-web-applications/
