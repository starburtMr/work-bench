# Skeleton Acceptance Checklist

## 项目运行

- [ ] 依赖可安装。
- [ ] 本地开发服务可启动。
- [ ] 首页可访问。
- [ ] 登录页或入口页可访问。
- [ ] 404 页面可访问。
- [ ] 构建命令成功。

## 技术方案

- [ ] 框架明确。
- [ ] 构建工具明确。
- [ ] UI 组件库明确。
- [ ] 路由方案明确。
- [ ] TypeScript 策略明确。
- [ ] 状态管理策略明确。
- [ ] API 策略明确。

## 目录结构

- [ ] app / pages / routes 位置清晰。
- [ ] modules 按业务域隔离。
- [ ] components 分层清晰。
- [ ] api 请求层统一。
- [ ] styles / tokens 独立。
- [ ] hooks/composables/utils/types 归位。

## 设计系统

- [ ] Token 文件已建立。
- [ ] 主色、文字、背景、边框、间距、圆角、阴影已定义。
- [ ] 组件库主题已接入。
- [ ] 页面无明显散落硬编码样式。
- [ ] 暗色模式或主题扩展位置已预留。

## 组件复用

- [ ] AppShell 可用。
- [ ] PageHeader 可用。
- [ ] EmptyState 可用。
- [ ] ErrorState 可用。
- [ ] LoadingState 可用。
- [ ] ConfirmDialog 可用。
- [ ] DataTable 或列表组件策略明确。

## 页面规格

- [ ] 每个页面有路由说明。
- [ ] 每个页面有角色说明。
- [ ] 每个页面有目标说明。
- [ ] 每个页面有状态说明：loading/empty/error/success/forbidden。
- [ ] 每个页面有响应式说明。

## API

- [ ] API Client 已建立。
- [ ] 错误结构已定义。
- [ ] Mock 策略已明确。
- [ ] 接口类型不散落在页面中。
- [ ] 页面状态与 API 状态对应。
