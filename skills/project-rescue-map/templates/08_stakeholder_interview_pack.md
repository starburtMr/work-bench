# Stakeholder Interview Pack

> 一次最多问 1 个会改变路径的问题。以下题库用于准备，不要一次性抛给用户。

## 1. 产品与范围

1. 当前 V1 必须完成的用户路径是哪一条？
2. 哪些功能已经明确不做，但代码里似乎已经出现了？
3. 最小可验收标准是什么？谁有最终验收权？
4. 项目失败的业务代价是什么：延期、成本、客户流失、合规、资金？

## 2. 数据与安全

5. 是否已经有真实用户/客户/生产数据？
6. 是否涉及支付、订单、权限、隐私、敏感身份信息或合规要求？
7. 是否允许重建数据库，还是必须保留现有数据？
8. migration 是否已经在任何共享环境执行过？

## 3. 技术与交付

9. 团队实际使用哪个包管理器、框架、部署平台？
10. 哪些依赖或技术是明确禁止的？
11. 现在有没有可以运行的本地环境？
12. 当前 CI 是否是合并门禁，还是摆设？
13. 是否有演示、交付或上线日期？

## 4. 组织与决策

14. 谁能决定“继续 / 重做 / 缩 scope / 暂停”？
15. 哪些历史决策不能改？为什么？
16. 是否有外包、前任团队、AI 生成代码或多人并行造成的漂移？
17. 目前最怕哪类事故发生？

## 5. 补救策略

18. 是否接受先冻结新增功能，只补真源和门禁？
19. 是否接受按子系统拆分补救，而不是一次性重构？
20. 哪些风险可以短期豁免，哪些绝对不能豁免？

## 推荐首问选择规则

- 如果不清楚项目根目录：先问根目录。
- 如果可能有生产数据：先问是否有生产/真实数据。
- 如果产品边界不清：先问 V1 必须闭环用户路径。
- 如果要判断继续/停止：先问谁有最终业务决策权和不可接受风险。
