# Subsystem Split Map

> 大型项目不要一口吞。先按用户路径、部署单元、数据域、团队边界或风险等级拆分。

## 1. 拆分原则

| 拆分维度 | 何时使用 | 示例 |
|---|---|---|
| 用户路径 | 产品范围混乱 | 注册登录、下单支付、后台审核 |
| 部署单元 | 多服务/多应用 | web、api、worker、admin、mobile |
| 数据域 | 数据风险高 | 用户、订单、账务、内容、审计 |
| 团队边界 | 多人/外包接手 | frontend team、backend team、data team |
| 风险等级 | 需要止血 | payment、auth、migration、secrets |
