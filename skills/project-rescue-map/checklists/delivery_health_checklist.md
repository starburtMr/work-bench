# Delivery Health Checklist

## 1. 可运行性

- [ ] README 的安装、启动、测试命令与实际脚本一致。
- [ ] 本地环境要求清楚：语言版本、包管理器、数据库、缓存、外部服务。
- [ ] `.env.example` 能覆盖代码实际读取的 env。
- [ ] 新人可以按文档启动最小本地环境。

## 2. 质量命令

- [ ] lint。
- [ ] typecheck。
- [ ] unit test。
- [ ] integration/contract test。
- [ ] build。
- [ ] e2e 或关键路径手工验收脚本。

## 3. CI/CD

- [ ] CI 跑真实质量命令。
- [ ] CI 与 README 命令一致。
- [ ] CI 有缓存但不掩盖失败。
- [ ] 合并门禁明确。
- [ ] 部署环境、release、rollback 清楚。

## 4. DORA 风格健康代理指标

> 补救阶段不一定有完整度量系统，但至少要寻找代理证据。

- [ ] 变更吞吐：最近变更能否小批次合并/发布。
- [ ] 变更前置时间：从 commit 到可验证环境的路径是否清楚。
- [ ] 变更失败：是否记录失败构建、回滚、线上事故。
- [ ] 失败恢复：是否有恢复流程、回滚脚本、备份、owner。
- [ ] 返工比例：是否大量修同一个范围、PR 反复回滚、任务反复重开。

## 5. 事故与复盘

- [ ] 是否有 incident log 或 postmortem。
- [ ] 是否记录影响、时间线、缓解动作、根因、后续动作。
- [ ] 是否避免个人归咎，聚焦系统性改进。
