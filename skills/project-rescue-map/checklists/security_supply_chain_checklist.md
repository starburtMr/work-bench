# Security and Supply Chain Checklist

> 这是补救诊断级检查，不替代专门安全审计。高危项发现后应停止普通开发并回到相应 skill 或安全流程。

## 1. Secrets 与配置

- [ ] 仓库中没有明文 `.env`、私钥、token、数据库密码、支付密钥。
- [ ] `.env.example` 存在且不含真实秘密。
- [ ] 代码读取的 env 与文档一致。
- [ ] 本地、测试、生产配置边界清楚。
- [ ] 构建、发布、运行阶段的配置职责清楚。

## 2. 认证与授权

- [ ] 登录态、session、JWT、CSRF、CORS 策略清楚。
- [ ] 后端执行权限校验，不只依赖前端隐藏按钮。
- [ ] 管理端、租户、角色、所有权检查有证据。
- [ ] 错误响应不泄露敏感信息。

## 3. 输入与数据安全

- [ ] 请求参数有校验。
- [ ] 文件上传有大小、类型、存储、扫描或隔离策略。
- [ ] 日志不记录密码、token、完整身份证/银行卡等敏感数据。
- [ ] 敏感字段有哈希、加密、脱敏或不存策略。
- [ ] 数据删除、导出、保留期限清楚。

## 4. 依赖与构建

- [ ] 包管理器和 lockfile 唯一。
- [ ] 依赖来源可信，未混入未知私有包或手工 vendored 二进制。
- [ ] CI 权限最小化。
- [ ] 构建命令可追溯，构建产物来源清楚。
- [ ] 发布流程能回滚。

## 5. 供应链参考信号

- [ ] 是否能运行 OpenSSF Scorecard 或等价检查。
- [ ] 是否具备 SLSA 思路下的 source/build/provenance 基础证据。
- [ ] 是否按 NIST SSDF 思路记录安全需求、实现、验证、响应证据。
- [ ] 是否按 OWASP SAMM 思路覆盖 Governance / Design / Implementation / Verification / Operations。

## 6. STOP 条件

- [ ] 任何真实密钥进入 git 历史。
- [ ] 任何生产数据可被普通诊断命令修改。
- [ ] 任何权限绕过影响真实用户/租户/资金/后台。
- [ ] 任何 migration 可能不可逆破坏共享环境数据。
