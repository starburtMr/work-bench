# 逆向DFD图分析

根据源代码逆向识别 DFD 的外部实体、加工、数据存储和数据流。

## 先读

- `references/dfd-style-and-rules.md`
- `templates/top-level-dfd.md`
- `templates/level-0-dfd.md`
- `templates/child-process-dfd.md`
- `templates/evidence-index.md`

## 输入类型判断

- **源代码**：读取路由、控制器、服务、实体、Repository、SQL、事件处理和页面组件。

输入材料中的页面、接口、函数、HTTP 请求、响应、数据库表和字段都是证据，不是 DFD 元素本身。必须先抽象，再入图。

## 代码证据索引

- 每次输出 DFD 图时，必须同步输出代码证据索引。
- 证据索引用来说明每个外部实体、加工、数据存储和数据流来自哪些代码证据。
- 证据至少标注到文件路径；能够确定时，继续标注路由、函数/类、数据库表、字段、事件名或页面组件。
- 证据不能替代抽象：页面、接口、函数、HTTP 请求、响应、数据库表和字段仍然只是证据，不直接等同于 DFD 元素。
- 如果某个 DFD 元素来自推断而不是直接代码证据，必须在证据索引中标注“推断”，并说明推断依据。

## 执行流程

1. **用户指定目标层级**
   - 不自动连续生成顶层图、0层图和后续分层图；只输出用户本次明确指定的目标层级。
   - 如果用户未指定目标层级，先询问用户要输出 `顶层图`、`0层图`，还是某个具体父加工的 `1层及后续图`，不要直接生成图。
   - 目标为 `顶层图` 时，顶层图只有一个加工，即系统本身，编号为 `0`。
   - 目标为 `0层图` 时，必须先判断是否已有或本次材料足以界定顶层图；如果没有顶层图基础，只提示“缺少顶层图，无法生成0层图”，并说明需要先输出顶层图。
   - 目标为 `1层及后续图` 时，必须先判断是否已有对应父层和父加工；例如输出 `1层图` 必须已有 `0层图` 中的父加工 `1`，输出 `1.2层图` 必须已有父加工 `1.2`。
   - 如果缺少前一层或缺少对应父加工，不生成目标层图，只提示缺少哪一层、哪一个父加工，以及应先生成的前置层级。
   - 分解加工 `1` 时编号为 `1.1`、`1.2`、`1.3`；分解加工 `2` 时编号为 `2.1`、`2.2`、`2.3`。
   - 继续分解时沿用父编号前缀，例如 `1.2.1`。
   - 即使用户指定更深层级，也不得跳过前置层级补画；只能提示前置层级缺失。

2. **画系统的输入和输出**
   - 画系统的输入和输出：在图的边缘标出系统的输入数据流和输出数据流。这一步其实是决定研究的内容和系统的范围。在画的时候，可以先将尽可能多的数据流画出来，然后再删除多余的，增加遗漏的。

3. **DFD的内部**
   - 将系统的输入、输出用一系列的处理连接起来，可以从输入数据流画向输出数据流，也可以从中间画出去。

4. **每一个数据流命名**
   - 命名的好坏与 DFD的可理解性密切相关，应避免使用空洞的名字。

5. **为加工命名**
   - 使用动宾短语为每个加工命名。

6. **输出 Mermaid DFD**
   - 判断是否属于复杂场景，确定需要遵守绘图规则的通用规则和复杂场景规则
   - 使用 Mermaid `flowchart` 表达 DFD。
   - 按层级写入MD文件

7. **输出代码证据索引**
   - 对本次图中的外部实体、加工、数据存储和数据流逐项列出证据。
   - 使用 `templates/evidence-index.md` 的结构输出证据表。
   - 证据不足的元素不得伪造来源；必须标注证据缺口。

## 输出模板

- 顶层图使用 `templates/top-level-dfd.md`，默认文件名为 `顶层图.md`。
- 0层图使用 `templates/level-0-dfd.md`，默认文件名为 `0层图.md`。
- 1层及后续图使用 `templates/child-process-dfd.md`，默认文件名为 `父加工<编号>分解图.md`，例如 `父加工1分解图.md`、`父加工1.2分解图.md`。
- 证据索引使用 `templates/evidence-index.md`，默认文件名为 `证据表.md`。
- 如果用户指定了输出目录或文件名，遵循用户指定；否则按上述默认文件名写入。
- 模板只规定落地结构，不改变 DFD 元素界定、分层门禁、编号规则、父子图平衡和 Mermaid 表达规则。
