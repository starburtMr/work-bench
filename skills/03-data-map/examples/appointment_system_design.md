# 示例：预约系统数据库设计

## 1. 业务流程

| 流程 | 角色 | 动作 | 读数据 | 写数据 |
|---|---|---|---|---|
| 浏览服务 | 用户 | 查看可预约服务 | services, staff, availability_slots | 无 |
| 创建预约 | 用户 | 选择服务、人员、时间段 | availability_slots | appointments |
| 改期 | 用户/员工 | 修改预约时间 | appointments, availability_slots | appointment_status_events |
| 取消 | 用户/员工 | 取消预约 | appointments | appointment_status_events |

## 2. 核心对象

- users：预约用户。
- services：可预约服务。
- locations：门店/地点。
- staff：服务人员。
- staff_services：人员可提供的服务。
- availability_slots：可预约时间段。
- appointments：预约主单。
- appointment_status_events：预约状态历史。

## 3. 关键关系

- location 1:N staff。
- service M:N staff，通过 staff_services。
- staff 1:N availability_slots。
- user 1:N appointments。
- appointment 1:N appointment_status_events。

## 4. 关键设计点

- 时间段冲突不能只靠前端判断。
- `appointments` 需要状态：`pending`, `confirmed`, `cancelled`, `completed`, `no_show`。
- 状态变化进入 `appointment_status_events`。
- 取消原因、取消人、取消时间要记录。
- 若有支付/押金，增加 payments。
- 若要避免并发抢同一时间段，必须有唯一约束或事务锁策略。

## 5. PostgreSQL 约束示例

```sql
CREATE TABLE appointments (
  id BIGINT GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
  user_id BIGINT NOT NULL REFERENCES users(id) ON DELETE RESTRICT,
  staff_id BIGINT NOT NULL REFERENCES staff(id) ON DELETE RESTRICT,
  service_id BIGINT NOT NULL REFERENCES services(id) ON DELETE RESTRICT,
  starts_at TIMESTAMPTZ NOT NULL,
  ends_at TIMESTAMPTZ NOT NULL,
  status TEXT NOT NULL DEFAULT 'pending' CHECK (status IN ('pending','confirmed','cancelled','completed','no_show')),
  cancel_reason TEXT,
  cancelled_at TIMESTAMPTZ,
  created_at TIMESTAMPTZ NOT NULL DEFAULT now(),
  updated_at TIMESTAMPTZ NOT NULL DEFAULT now(),
  deleted_at TIMESTAMPTZ,
  CHECK (ends_at > starts_at)
);

CREATE INDEX appointments_user_created_at_idx ON appointments(user_id, created_at DESC);
CREATE INDEX appointments_staff_time_idx ON appointments(staff_id, starts_at, ends_at);
```
